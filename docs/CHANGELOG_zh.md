## v2.0-beta.3

> **重新发布。** 最初的 `v2.0-beta.3` 已撤回 —— 它在版本比较和自更新地址的修复
> 落地之前就打好了,导致它自己永远无法更新。

### 🔴 macOS:打包版根本跑不起来

`v2.0-beta.2` 及之前**每一个** macOS 下载包都有四个各自独立的问题,而且四个都
不报错。现在全部修复。

- **手工拼出的 `.app` 从未重新签名。** PyInstaller 的二进制自带一份 bundle 形态的
  签名;把它拷进手工壳里,两者互相矛盾,`codesign --verify` 失败,macOS 报
  *「已损坏,无法打开」*。右键打开也没用 —— 那是签名校验失败,不是"未验证开发者"。
  构建脚本现在会重新签名,并且**签名校验不过就让构建失败**。
- **`ditto -c -k` 把扩展属性写成 AppleDouble 附属文件,摆在 `.app` 里面。**
  `ditto` 自己认得,但 Keka 和 `unzip` 不认,把它们当普通文件留在包里,破坏了封印。
  **能不能用取决于你用什么工具解压。** 现在用 `--sequesterRsrc` 打包,附属文件
  被挪到包外面。
- **数据目录用相对路径。** `.app` 从 Finder 启动时工作目录是 `/`,只读,建
  `shots_data/` 抛 `OSError: [Errno 30]`,进程直接退出 —— 用户看到的是
  *「双击了,什么都没发生」*。打包版现在用
  `~/Library/Application Support/PrintTheShot/`;源码运行行为不变。
- **打包版 stdout 是断开的**(`argv_emulation`),启动横幅和异常堆栈全都无处可去。
  现在输出会同时写一份到数据目录下的 `server.log`。

### 🍎 macOS 现在有两个架构

产物以前**只有 arm64** —— GitHub Actions 上的 `macos-latest` 是 Apple Silicon
机器,而这件事没有任何地方写明,所以 Intel Mac 用户根本跑不起来。

| 文件 | 适用 |
|---|---|
| `PrintTheShot-macos-arm64.zip` | Apple Silicon(M 系列)|
| `PrintTheShot-macos-intel.zip` | Intel |

CI 现在每次构建都会校验产物架构与 runner 是否匹配、签名是否有效,这两个问题都
不可能再悄悄回来。

### ✨ 能停掉它,也知道它起来了

打包后的 macOS 应用是后台服务:没有窗口、没有 Dock 图标、没有终端。

- **启动时会自动打开管理界面**,否则用户无从判断它到底起来没有。
- **状态卡片里有红色的「停止服务」按钮** —— 只在 macOS 版出现,因为只有那种形态
  没有别的停止方式。Windows 有关掉控制台窗口,Linux 通常就在终端里跑。服务端会
  先回响应再停止,所以确认消息能正常到达。**该端点不限来源 IP**:局域网内任何
  设备都能调用。
- **日志文件**在 `~/Library/Application Support/PrintTheShot/server.log`。
- 应用声明为 `LSUIElement`,修掉了 Dock 图标一直跳的问题。
  (PyInstaller 用 `console=True` 打的是控制台程序,永远不会完成 macOS 的启动握手,
  而 `CFBundlePackageType` 又是 `APPL` —— 于是图标无限停留在"正在启动"状态。)

### 🐛 自更新从未生效

两个各自独立就足以致命的 bug:

- **版本比较只看 `major.minor`。** `2.0-beta.2` 和 `2.0-beta.3` 都解析成 `(2, 0)`,
  比出来相等,于是「检查更新」报「已是最新」。现在预发布序号纳入比较,且正式版
  排在同名预发布之后。
- **更新地址指向原项目仓库**,而那里是 v1.6。远端版本恒读为 `1.6`。现在改成用
  一个常量指向本项目自己的仓库,以后再换只改一行。

两者都没酿成事故,只是因为 `1.6` 比当前版本号小,更新按钮保持禁用。**万一那个
仓库的版本号被改大,就会把用户降级,并用 v1.6 覆盖掉服务端源码。**

### 📄 文档

- macOS 的放行步骤现在写进了下载表格本身,而不是表格下方的注记;并且明确区分
  *「无法验证开发者」* 与 *「已损坏」* —— 后者绕不过,`xattr` 也修不了。
- 新增本文件;此前 `CHANGELOG.md` 顶部的「中文」链接指向的是它自己。

## v2.0-beta.2 (2026-08-05)

### ✨ 新功能

**1. DeepSeek AI 翻译**
- ⚙ 设置子页面:API key 输入、启用开关、**实时余额显示**(官方 DeepSeek 余额接口)
- **自定义语言**:输入任意语言名(日本語 / Japanese / 日语 都行)或从常用预设里选;AI 批量翻译全部约 85 条界面文案;语言切换器自动扩展
- 卡片 **🌐 翻译按钮**:语言选择对话框(自定义语言自动添加)→ AI 翻译豆子信息(产地/风味/烘焙度)+ 冲煮方案 → **整张图表按目标语言重渲染**,然后弹出大图
- **大图语言 chips**:在已缓存的语言版本间即时切换,不消耗 API
- 翻译只存在于缓存,**统计不受影响**;8 秒超时回退原文,绝不阻塞打印

**2. 语言一致性**
- 记录始终保留原始语言;卡片标题 / 统计在展示层翻译(静态映射表 + AI 缓存)
- `chart_lang` 记录每张图的语言;网格在后台按当前界面语言重渲染(仅用缓存,每页最多 36 张)
- 任何界面语言下都不会残留其他语言的文字

**3. 打印 / 图表质量**
- 右栏:按**实测宽度换行**(修掉日文全角溢出),字号按文本长度自适应,拉丁字母语言小 2px
- 豆子信息自动清理 `·` 与 `-` 分隔符
- AI 提示词要求输出简洁(不再出现超长的法文标题)

**4. 界面打磨**
- 卡片操作改为图标:🖨️ 📄 🖼️ 🌐
- 大图操作栏:打印 / 下载 JSON / 下载 PNG / 翻译 / 切换语言
- 设置移到子页面(右上角 ⚙)
- 状态卡片显示 AI 余额

**5. 数据与工具**
- 测试数据生成器支持 `zh|en` 两套数据(豆子/方案/烘焙度双语)
- 可生成一个月模拟数据(31 天 × 约 50 条 = 1670 条)

### 🐛 修复
- 切换语言导致页面崩溃(英文文案里的撇号破坏了 JS 注入 → 用 `&#39;` 转义)
- AI 提示词用了内部语言代码(`lang1`)而不是显示名 —— 翻译结果是错的
- 缺少 `import re`,翻译时报 NameError
- 大图显示浏览器缓存的旧图片
- 网页标题的版本号缺失(只有一个 "v" 后面什么都没有)
- 上传不再自动调用 AI 接口(省 token;只在需要时翻译)
